# Data Model

Schema source of truth: `src/main/resources/db/migration/`.

**Invariant:** `product.quantity_on_hand` always equals the sum of that product's `stock_movement.quantity_delta`, and is always `>= 0`.

## `product`

The catalogue of items we track. One row per SKU, with a denormalised current balance.

| Column | Type | Description |
|---|---|---|
| `id` | BIGINT identity, PK | Surrogate key, generated by the database. |
| `sku` | VARCHAR(64), unique, not null | Business identifier (stock keeping unit). Unique; a duplicate returns 409. |
| `name` | VARCHAR(200), not null | Human-readable product name. |
| `description` | TEXT, nullable | Optional free-text details. |
| `unit` | VARCHAR(32), not null | Unit of measure for quantities (e.g. `pcs`, `kg`, `box`). Quantities are integers. |
| `reorder_level` | INTEGER, default 0, `>= 0` | Restock threshold. If `quantity_on_hand <= reorder_level` the product is low stock (badge, `?lowStock=true`, dashboard). |
| `quantity_on_hand` | INTEGER, default 0, `CHECK >= 0` | Current balance. Always starts at 0; initial inventory is a `RECEIPT` movement. Only changed by the movement service, in the same transaction as the movement, under a pessimistic row lock. The CHECK is the last line of defence against negative stock. |
| `active` | BOOLEAN, default true | Soft-delete flag. `DELETE /api/products/{id}` sets it to false; rows and history are never removed. |
| `created_at` | TIMESTAMPTZ, not null | When the product was created. Set by the app from the injected `Clock` (no DB default) so seed data can be back-dated. |
| `version` | BIGINT, default 0 | Optimistic-locking counter (JPA `@Version`). Hibernate adds `WHERE version = ?` to updates and increments it, so two concurrent product edits cannot silently overwrite each other. Managed by Hibernate; never set manually. |

Constraints: `uq_product_sku`, `ck_product_quantity_non_negative`, `ck_product_reorder_level_non_negative`.

## `stock_movement`

Append-only ledger. Every stock change is one row; rows are never updated or deleted.

| Column | Type | Description |
|---|---|---|
| `id` | BIGINT identity, PK | Surrogate key. |
| `product_id` | BIGINT, FK to `product(id)`, not null | The product whose stock changed. |
| `type` | VARCHAR(16), not null | `RECEIPT` (stock in, positive), `ISSUE` (stock out, negative delta), or `ADJUSTMENT` (manual correction, signed). Enforced by `ck_movement_type`; stored as a string for `@Enumerated(EnumType.STRING)`. |
| `quantity_delta` | INTEGER, not null, `<> 0` | Signed change applied to the balance. The API takes a positive quantity for `ISSUE`; the service converts it to a negative delta. Zero is rejected. |
| `balance_after` | INTEGER, not null, `>= 0` | The product's `quantity_on_hand` immediately after this movement. Lets history and balance-over-time be read without re-summing the ledger. |
| `note` | VARCHAR(500), nullable | Optional reason or reference (e.g. "supplier delivery", "damaged"). |
| `created_at` | TIMESTAMPTZ, not null | When the movement happened. Set from the `Clock`; back-dated by the seed loader. |

Constraints: `ck_movement_type`, `ck_movement_delta_non_zero`, `ck_movement_balance_non_negative`.

Index: `idx_stock_movement_product_created (product_id, created_at DESC)` serves the "newest first" history query per product (Postgres does not index FK columns automatically).

## Locking strategy

- **Movements:** pessimistic lock (`SELECT ... FOR UPDATE` on the product row), so concurrent movements serialise and cannot oversell or lose updates.
- **Product edits** (name, description, reorder level): optimistic locking via `version`, since conflicts are rare.
